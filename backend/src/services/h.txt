# Phase 10.31 — Conversation turn-state exposure

> Root: 0eaac09 `AI: resume instruction after approval`
> This phase: `AI: expose conversation approval state`

## Goal

Expose the complete turn state of every AI conversation in the authenticated
history API so a caller can tell, for each conversation, whether the last
turn is `completed`, blocked on a decision (`awaiting-approval`), or ended in
a terminal tool state (`approved` after approve+resume, `rejected`, `expired`)
or `failed` — plus every currently-actionable pending approval. Both
`GET /api/ai/conversations` (list) and `GET /api/ai/conversations/:id`
(detail) now return `turnState` and `pendingApprovals` alongside their
existing shapes; nothing else about the existing response or error envelopes
changes.

## What changed

### Persistence (`agentConversations`, `aiToolApprovals`)
- `agentConversations.listConversationLastMessages(userId, conversationIds)`
  returns each OWNED conversation's LAST transcript row (chronological
  `(createdAt, id)` order) as `{ conversationId, messageId, role, isFinal }`.
  Ownership is enforced via the `conversation: { is: { userId } }` relation,
  so a foreign conversation is indistinguishable from a missing one; empty
  input returns `[]` without a database read.
- `aiToolApprovals.listToolApprovalsForConversations(userId, conversationIds)`
  returns EVERY owned approval across the conversations in ALL states
  (pending/approved/rejected/expired), oldest-first (`createdAt` asc, then
  stable `id`). Empty input short-circuits to `[]`.

### Safe projection (`aiToolApprovals` service)
- New shared `AiToolApproval` shape + pure `toAiApproval(record)`: ids, tool
  name, validated arguments, status, ISO timestamps (`createdAt`/`updatedAt`/
  `expiresAt`), `decidedAt`. The owner's `userId` is dropped (implied by
  authentication). The route's private `toApprovalResponse` was replaced by
  this shared projection, so the approvals API and the conversation history
  API project through ONE content-free representation.
- Service `listConversationToolApprovals(userId, conversationIds)` wraps the
  repo read through `toAiApproval`.

### Turn-state derivation (`aiConversations` service)
- New `AiTurnState`: `completed | awaiting-approval | approved | rejected |
  expired | failed`. `AiConversationSummary` and `AiConversationDetail` gain
  `turnState` + `pendingApprovals` (extending a shared `AiConversationSummaryBase`).
- `deriveConversationTurnState(isFinalReply, approvals, now)` — pure and
  deterministic:
  1. Any actionable pending approval (status `pending` AND `now < expiresAt`)
     → `awaiting-approval`; `pendingApprovals` is exactly these actionable
     rows, so an expired window is never surfaced as decidable.
  2. Otherwise the approval with the most recent `updatedAt`: `approved` /
     `rejected` by status, else (a pending row whose window elapsed) →
     `expired`.
  3. Otherwise, by the last transcript row: `is_final` assistant reply →
     `completed`, else `failed`.
- The derivation uses ALL of the conversation's approvals — deliberately NOT
  the last user-message's slice — because after approve+resume (10.30) the
  consumed approval belongs to the EARLIER segment while the persisted reply
  is from the resumed round; per-segment filtering would misclassify a
  resumed turn as `completed`.
- Enrichment is batched (`list` runs `listConversationToolApprovals` +
  `listConversationLastMessages` in parallel over the listed ids); `detail`
  enriches AFTER the existing 404 check, so a foreign/missing conversation
  never triggers an approvals query.
- No tool execution, provider call, or network ever happens on these paths.

# Phase 10.32 — Desktop AI conversation read-only UI foundation

> Root: 925ea5e `AI: expose conversation approval state`
> This phase: `AI: add desktop conversation view`

## Goal

Add the first real desktop frontend surface over the authenticated AI
conversation/history APIs: a read-only conversation view (main `ai-assistant`
view AND the Smart Assistant side panel) that renders ONLY persisted data —
real user/assistant messages, the server-derived `turnState`, and, when the
backend returns them, still-decidable approvals as read-only cards. No
approve/reject actions, no tool execution from the frontend, no fabricated
conversations/messages/approvals. Backend ownership/security stays
authoritative; the frontend never infers permission or approval authority. A
minimal, centralized, in-memory frontend session abstraction is introduced so
the view can call the existing authenticated APIs. No backend changes were
required — the 10.31 contract was sufficient.

## Frontend changes (all under `web/`)

### Session / auth (centralized, in-memory)
- `src/services/session.ts` — the single owner of the bearer token. Rules:
  token held in a module-level variable only; never in component state, never
  in URL/query parameters, never persisted to localStorage/sessionStorage (no
  secure OS-backed credential vault exists in the surrounding Tauri
  architecture yet; after a reload the app shows the sign-in state again).
  Reuses ONLY the existing `authApi` endpoints. Exposes `login` (stores
  user+token, returns the user), `logout` (best-effort server revoke via the
  EXISTING `POST /api/auth/logout`, then always clears local state),
  `requireSessionToken` (throws `SessionNotAuthenticatedError` before any
  unauthenticated request is issued), plus `subscribeSession`/`getSessionSnapshot`
  for React's external store. No second authentication system.
- `src/services/useSession.ts` — `useSyncExternalStore` binding returning
  `{ user, isAuthenticated, login, logout }`; components never see the token.
- `src/services/api/index.ts` — added `authApi.logout(token)` (the endpoint
  already exists; only the typed client was missing).

### Authenticated API client
- `src/services/api/aiConversations.ts` — `listAiConversations()` and
  `getAiConversation(id)` pull the token via `requireSessionToken()` at call
  time and pass it to the existing `apiRequest` (`Authorization: Bearer`).
  Unauthenticated calls fail fast with `SessionNotAuthenticatedError` and
  never hit the network. Ownership/404 semantics come straight from the
  backend envelope (typed `ApiClientError`).
- `src/types/ai.ts` — frontend types mirroring the exact backend JSON for
  `AiTurnState`, `AiConversationSummary`, `AiConversationDetail`,
  `AiHistoryMessage`, and `AiToolApproval`.

### Read-only conversation UI (shared by both surfaces)
- `src/components/conversations/TurnStateBadge.tsx` — pill for every
  server-derived turn state (list shows only non-completed states; the
  transcript header always shows its badge).
- `src/components/conversations/ConversationList.tsx` — real persisted
  conversation rows (title or "Untitled conversation", updated date, turn
  badge when relevant), newest-first as returned by the API.
- `src/components/conversations/ConversationTranscript.tsx` — loading, error
  (incl. conversation-not-found) and ready states; renders the persisted
  messages chronologically (user right-aligned, assistant with avatar),
  minimal safe tool-call/result metadata, a turn-state banner for every
  relevant state (awaiting-approval/approved/rejected/expired/failed), and
  pending approvals attached to their originating message id (strays grouped
  under a "Pending approvals" block).
- `src/components/conversations/ApprovalCard.tsx` — READ-ONLY card rendering
  only safe metadata (tool name, validated arguments as key/value, status,
  expiry). Deliberately renders NO approve/reject controls and states so.
- `src/components/conversations/SignInPanel.tsx` — sign-in form reusing the
  existing login abstraction; errors surface the backend message; token never
  enters the URL or component state.
- `src/components/views/AIHistoryView.tsx` — new main `ai-assistant` view:
  header (user + refresh + sign out), list pane, transcript pane, auto-select
  of the newest conversation, empty/loading/list-error/detail-error handling,
  and a full-panel sign-in state when no session exists.
- `src/components/AIAssistant.tsx` — the side panel now reads the SAME data
  through the same session + API; the prior placeholder chat (canned messages,
  quick prompts, composer, send button) was removed entirely.
- `src/App.tsx` — `view === "ai-assistant"` now renders `<AIHistoryView />`
  instead of the placeholder text.
- `src/components/Icons.tsx` — added `RefreshCw` and `LogOut` (existing helper
  pattern).

### Test tooling (web)
- Added devDependencies + `test` (`vitest run`), `test:watch`, and `typecheck`
  (`tsc --noEmit`) scripts; `vitest.config.ts` (jsdom + `@` alias +
  `src/test/setup.ts` importing `@testing-library/jest-dom/vitest`).
